# Use an explicitly bounded settlement-time price

The inspected testnet oracle provides current prices rather than historical prices at a selected timestamp. Reckon therefore resolves a prediction using the price returned by the first successful valid oracle request initiated after its deadline and completed within a bounded settlement window, with a void and challenger refund if no valid result arrives in time. The rule is visible before staking and discloses that caller timing and source caching can affect outcomes, trading exact-time measurement for a simpler live settlement path.

Accepted by the user during the grill-with-docs interview on 13 November 2026, IST. For the first implementation, the request completion window is 120 seconds after the prediction deadline. The longest recorded paid callback took 50.356 seconds; 120 seconds gives margin over that observation. The sample is small and does not establish a safe tail latency or prove future paid refresh success. A request is serialized per prediction and identified in its callback; callbacks must complete strictly before the cutoff. At or after the cutoff, a caller can void the round, refund the challenger, and release the commitment. The contract's block timestamp is authoritative for requests, callbacks, and voids. The keeper reads an optimistic block timestamp before submitting a transaction, so RPC or transaction delay can make the contract reject a request; its next poll can void after the cutoff. The browser uses the device clock only to estimate displayed deadlines and can appear early or late; chain acceptance decides challenge and settlement. Provider validation checks the configured oracle, receiver, request identity, exact response shape, `wrap.near` asset, positive multiplier, decimal units, response timing, and the provider's documented 300-second recency semantics. The outer oracle timestamp is not an external market observation timestamp.
